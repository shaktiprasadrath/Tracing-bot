# Round 1 Architecture Review — Performance, Scalability & Data Architecture

**Reviewer lens:** performance / scalability / data architecture
**Scope reviewed:** `Tracing-Bot-PRD.md`; `docs/architecture/00`–`05`; `docs/architecture/features/F01`–`F12`, `X-SEC`, `X-OPS`
**Date:** 2026-09-14 · **Round:** 1

---

## 1. Verdict

# REJECT

The intent is right and the document set is unusually complete for a round-1 review. But the storage
tier cannot meet its own headline gate (D-T1 indexed attribute search) because the feature-level hot
index has no span rows at all; the hot-index sizing arithmetic in `01 §5.1` is wrong by ~4× before
index amplification and exceeds the configured disk budget by itself; the cold store is specified two
incompatible ways (128 MiB row groups vs. one row group per trace) with a crash-consistency hole
between the tiers in both directions; the sampler's trace-assembly memory bound and its sharding
scheme are each specified three or four different ways across `01`/`02`/`04`/`F02`/`X-OPS`; and three
package import cycles that `02 §5` explicitly declares broken are re-introduced by the feature authors
(and one by `02` itself). The eval harness — the artifact that is supposed to make the accuracy claims
credible (D-D5) — bypasses the pipeline it is meant to measure and cannot run deterministically or
inside its stated CI budget.

These are not tuning items. They change the schema, the write path, the sharding contract, and the
package graph. Re-review after a revision pass.

**Counts:** 16 Blocker · 14 Major · 5 Minor

## 3. Positive notes

- **The backpressure contract is the strongest part of the design.** `01 §3.1`'s stage table and `04 §4`'s
  concurrency table name every channel, its capacity, and its full-behaviour, and `04 §6` states the
  invariants explicitly ("bounded everything", "nothing is lost silently"). Most systems at this stage
  have none of this. The blockers above are mostly *inconsistencies with* this model, not absences of it.
- **Loss accounting is designed in, not bolted on.** `ReasonShed`, `ReasonTruncated`, `shard_full`,
  `Trace.Truncated`, `ToolResult.Truncated`, `traceiq_topology_edges_evicted_total` — every lossy path
  has a named counter and, where it is user-visible, appears in the artifact. This is the right instinct
  and makes the RED-accuracy gate testable once PD-25 is fixed.
- **RED extraction before discard (P6) is the correct core idea** and is what makes aggressive tail
  sampling defensible. It needs the three holes in PD-25 closed, not a redesign.
- **`02 §5`'s cycle-break table is exactly the right artifact** — including the decision to enforce it with
  an `archtest` in CI. PD-15 is a failure to honour it, not a failure to have designed it.
- **`05 §D-3`/`§D-5` show real engineering judgement**: rejecting CGO SQLite for C1, rejecting Kafka as a
  default, pinning versions against a verified toolchain, and pre-registering `FU-3` as a benchmark gate
  rather than asserting a throughput number. Fix the premise (PD-2) and the gate is the right mechanism.
- **The tiered retention model (`01 §5.3` T0–T6) is well-formed** — distinct tiers, distinct config keys,
  a defined shed order that protects anomalous data last. It is the sizing arithmetic (PD-1) and the
  cold-tier mechanics (PD-4, PD-23), not the policy model, that need work.
- **Cost is treated as a first-class, capped, observable quantity** (`P5`, `rca.budget.*`,
  `store.budget.*`, `store_hot_index_ratio`) rather than an afterthought — the right answer to D-D1.
