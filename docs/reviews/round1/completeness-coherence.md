# Architecture Review — Round 1 — Completeness, Traceability, Design Coherence

**Reviewer lens:** completeness · drawback traceability · cross-document coherence
**Scope reviewed:** `Tracing-Bot-PRD.md`; `docs/architecture/00`–`05`; `docs/architecture/features/F01`–`F12`, `X-SEC`, `X-OPS`
**Date:** 2026-09-14 · **Round:** 1

---

## 1. Verdict

> ## **REJECT**

The system documents (00–05) describe one system; the fourteen feature documents describe a different, partially incompatible one. This is not stylistic drift. Three feature docs declare Go types that create import cycles the class diagram explicitly forbids and that CI is specified to fail on (CC-1). The three headline differentiators — the closed sampler/agent loop (D-X5), investigation-gated paging (D-D4), and replayable RCA (D-Y1) — each have two or three mutually exclusive definitions across the set (CC-2, CC-3, CC-4). The owning feature docs for two more marquee claims (fast attribute search, cost-linearity) do not contain the mechanism that 01 §9 says resolves the drawback (CC-9, CC-23).

Individually most of these are fixable in a day. Collectively they mean no implementer can pick up F0x and build something that links against F0y, and no reviewer can tell which number is the acceptance gate. The catalog (00) is nominally the source of truth for interface names, but every feature author extended it independently and nothing was reconciled back into 01/02. Round 2 should be gated on the reconciliation table in §4 being applied to 00/01/02 **first**, then the feature docs rewritten against it — not the other way round.

What is genuinely strong and should not be re-litigated: the ADR (05) is the best document in the set — evidence-based, with a compiled verification section and an honest P0 toolchain blocker; 01 §8 (security architecture) and 04 (execution flow) are implementable as written; F07 and F01 are internally coherent and fully AC-covered; the `model.InvestigationRecord` / `model.ActionProposal` cycle-breaking design in 02 §5 is exactly right — the feature docs simply ignored it.

## 6. Requirements quality

- **Numbers.** Most FRs are commendably numeric (F01, F02, F03, F04, F07 are exemplary — every FR carries a threshold and a measurement method). The failure mode is not vagueness but *contradiction*: the same gate has two values in two docs (CC-11). A reviewer cannot tell which number a test should assert.
- **FR without AC:** 33 instances across nine documents (CC-29). Every one of F09's approval-channel, snapshot-ordering, Slack-signature and audit-pagination requirements is uncovered — in the one feature that mutates production.
- **AC without FR:** none found. Coverage failure is one-directional.
- **Untestable predicates:** four (CC-30) — "tier-0-labeled service", "configurable dollar ceiling … set in config", "fingerprint family", "expected evidence categories".
- **AC ID discontinuity:** F09 (1,2,3,4,7), F11 (1,4,7,9), F12 (1,5,6,8,10), X-SEC (1,3,5,7,9). Either ACs were dropped in editing or the numbering encodes a mapping nobody documented; both need fixing before the traceability matrix means anything.
- **Cross-doc gate ownership:** several 01 §10 targets are owned by no feature doc and therefore by no test — indexed attribute search p95 ≤ 250 ms (D-T1 gate), alert precision ≥ 80 % (D-D4 gate), RCA accuracy ≥ 70 %/≥ 40 % (D-D5 published numbers), investigation cost ≤ $0.50, RED aggregate accuracy ≤ 0.5 %/≤ 2 % (this one *is* owned, by F02 FR-F02-5/AC-F02-5 — the model to follow).
