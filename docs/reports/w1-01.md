## Ambiguities / judgment calls (most-literal reading taken)

1. **DR-7's dev block-seal sizes.** DR-7 §6.5 states parenthetically "dev: 32 MiB / 128 MiB /
   5 m" for `row_group_bytes`/`target_block_bytes`/`flush_interval`, which is smaller than the
   general figures the original doc stated in the §5.2 intro (128 MiB / 512 MiB). DR-9 then
   explicitly drops `max_open_blocks` 4→2 "so the RSS sum closes," which only works with the
   32 MiB row group. I took DR-7's explicit dev parenthetical literally, applied it to the
   `store.cold.parquet.*` config defaults (since the config represents the dev/MVP profile),
   and kept 512 MiB/128 MiB as the "general/prod [P2]" figures cited alongside. A different
   reading would keep the original 128/512 MiB values and treat DR-9's "row_group_bytes to
   32 MiB" instruction as the only override (leaving target_block_bytes at 512 MiB) — worth a
   second look against `05` if that document is later found to assume 512 MiB.
2. **DR-3's "§4 reference, not re-declaration."** `01 §4` never previously declared
   `tenant.Policy`/`tenant.Resolver`/etc., so there was nothing to delete. I added a one-line
   citation note instead of a new subsection, per the "append sub-sections, never renumber"
   rule not obviously licensing a new numbered §4.8 for a single sentence.
3. **`model.REDSample.Tenant` left as `string`.** DR-4 introduced `TenantID` and I converted
   it on `Span`, `Trace`, and `InvestigationRecord`, but deliberately left `REDSample`
   unconverted because DR-39 (not yet applied) replaces the entire `REDSample` struct
   ("01 §4.1 (the struct above)") — converting it now would just be redone/possibly
   contradicted by DR-39's replacement shape.
4. **`model.ActionProposal.Params map[string]string` left untouched.** DR-22 (not yet applied)
   deletes this field and replaces it with typed proposal specs; DR-4 only asked for §4.1 to be
   "normative and complete" for the types it listed, and `ActionProposal` details are DR-22's
   to rewrite, so it was left as-is rather than half-migrated.
5. **`Tenant string` fields in §4.2–§4.7** (sampler.Decision, anomaly.Event/Incident,
   rca.Investigation/Step/Evidence, remediate.Action, memory.Record, topology.Edge) were
   **not** converted to `TenantID` in this pass. DR-4's binding block only enumerated §4.1
   additions; each of those subsections has its own owning DR (DR-10, 11, 13, 14, 15, 17–19,
   22–23) still pending, and converting the field type without also applying that DR's other
   changes risked leaving the section in a half-updated state the report couldn't cleanly
   describe as "applied."
