## Ambiguities / judgment calls (most-literal reading taken)

1. **Package renames to `model` for previously `anomaly`/`rca`/`remediate`/`memory`-scoped
   types**, continuing the pattern from `w2-01.md`'s checkpoint: DR-14/15/17/18/19/23 all write
   interface signatures using `model.AnomalyEvent`, `model.Incident`, `model.Investigation`,
   `model.Step`, `model.Evidence`, `model.Action`, `model.Record`, etc. — impossible unless
   those types live in the leaf package `model` (DR-2). Took the literal reading throughout.
2. **`model.CriticalSLOBreach`/`SLOObjective` placed in `§4.3`** despite DR-21's "Docs to
   change" line not naming a `§4` target — the type is `package model` per DR-21 §21.2 and is
   referenced by the new `alerting.critical_slo_breaches` key added to `§7`.
3. **`model.Correction` fields** (`{Note, By, At}`) are the task's own invention, since the
   register's `Engine.Correct(..., c model.Correction)` signature never defines the type's
   fields. Based on the old `Step.CorrectionNote`/`CorrectedBy` fields it replaces.
4. **`Step.HypothesisID`/`Thought`/`Corrected*` dropped**, not carried forward — DR-18 §18.1's
   `Step` struct verbatim has no such fields; consistent with `§1.1` P3 (corrections live in
   memory, not on the step) and `Hypothesis.TestStepIDs` already providing the reverse link.
5. **`ActionProposal.EvidenceIDs` dropped** — present pre-DR-22, absent from DR-22 §22.1's
   verbatim replacement, so removed as a straight deletion.
6. (superseded by #2 above in this pass's numbering — kept for continuity with `w2-01.md`.)
7. **`memory.Fingerprint` kept in package `memory`, not `model`** — DR-19 §19.1's code block
   explicitly says `package memory` for `Fingerprint`/`Compute`, unlike `Record`.
8. **`ops.shutdown_grace` not duplicated.** DR-33 §33.3's YAML shows `ops: shutdown_grace: 45s`
   nested under `ops`, but `01` already has `server.shutdown_grace: 45s` (established in an
   earlier round, cited throughout `§10.3`/`§3.1`). Added only `ops.backup.*` and left
   `shutdown_grace` under `server.*` to avoid two sources of truth for the same key; noted
   inline in the config comment.
9. **DR-38's "every row names an FR" only partially done.** Added explicit `FR-Fxx-yy`
   citations only where the register itself supplies the ID for that row (D-D1: FR-F03-15/
   FR-F06-17; D-D4: FR-F12-14/FR-F12-15). The other ~20 `D-*` rows predate this register and
   have no FR ID given anywhere in `06-decision-register.md`; inventing FR numbers for them
   would be fabrication rather than verbatim application, so they were left citing feature IDs
   (F05, F06, ...) as before. Flagged rather than guessed, per the task's own tie-breaking rule.
10. **DR-30's `api.Server`→`api.HTTPServer`/`api.Deps` rename not applied to `01`.** DR-30's
    "Docs to change" line lists this rename only for `F12 §4.2`, not for `01`; `01 §1.2`'s
    `api.Server` mention was left as-is since changing it wasn't in scope for this document
    per that DR's own instruction.
11. **DR-14/DR-30's `D-T3` edit folded together.** While applying DR-30's per-row screen
    citations to `§9`, the D-T3 row's secondary clause was also struck per DR-38 §38.1 in the
    same edit, since both touch the same table cell and re-editing it twice would have been
    wasteful. Recorded under both DRs above.
